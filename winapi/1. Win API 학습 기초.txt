1. Win API 학습 기초 
Windows 프로그래밍의 기초
목표
Win32 API의 가장 기본적인 구조를 이해하고, 화면에 빈 창(Window) 하나를 띄울 수 있게 됩니다. 이 과정을 통해 모든 Windows 애플리케이션의 뼈대가 되는 핵심 개념들을 익힙니다.

Windows 프로그래밍의 핵심 흐름
Windows 프로그램을 만드는 것은 크게 4단계의 과정을 거칩니다.

프로그램 시작점(WinMain) 설정: 프로그램이 시작되는 곳입니다.

윈도우 설계도(WNDCLASSEX) 작성 및 등록: 어떤 모양과 특징을 가진 창을 만들지 정의합니다.

설계도를 바탕으로 윈도우 생성: 실제 윈도우 객체를 메모리에 만듭니다.

메시지 루프 실행: 사용자의 입력(키보드, 마우스 등)을 받아 처리하고 윈도우가 꺼지지 않게 유지합니다.

이제 각 단계를 자세히 살펴보겠습니다.

1. WinMain 함수: 모든 것의 시작
C/C++의 main 함수처럼, Win32 애플리케이션은 WinMain 함수에서 시작합니다.

int WINAPI WinMain(HINSTANCE hInstance, HINSTANCE hPrevInstance, LPSTR lpCmdLine, int nCmdShow)

hInstance: 운영체제가 프로그램에 부여하는 고유 ID입니다. 프로그램 자체를 나타내는 핸들(Handle)로, 앞으로 윈도우를 만들거나 리소스를 사용할 때 계속 사용됩니다.

hPrevInstance: (과거 유물) 16비트 Windows 시절에 사용되던 것으로, 지금은 항상 NULL입니다.

lpCmdLine: 명령줄(Command Line)로 프로그램에 전달된 인자입니다.

nCmdShow: 프로그램의 윈도우를 어떻게 보여줄지(예: 최소화, 보통 크기)에 대한 값입니다.

2. WNDCLASSEX: 윈도우 설계도 만들기
윈도우를 만들기 전에, 어떤 특징을 가진 윈도우를 만들 것인지 WNDCLASSEX 구조체에 정의해야 합니다.

cbSize: 구조체의 크기입니다.

style: 윈도우의 스타일을 지정합니다. (예: 창 크기가 변할 때 다시 그릴지 여부)

lpfnWndProc: 가장 중요합니다. 이 윈도우에서 발생하는 모든 이벤트를 처리할 함수(윈도우 프로시저)를 지정합니다.

hInstance: 이 윈도우 클래스를 등록할 프로그램의 인스턴스 핸들(WinMain에서 받은 hInstance)입니다.

hIcon, hCursor, hbrBackground: 윈도우의 아이콘, 마우스 커서, 배경색 등을 지정합니다.

lpszClassName: 이 윈도우 설계도의 고유한 이름입니다. 나중에 CreateWindowEx에서 이 이름을 사용합니다.

이 설계도를 작성한 후, RegisterClassEx(&wcex) 함수를 호출하여 운영체제에 "이런 종류의 윈도우를 사용할 거야"라고 등록해야 합니다.

3. CreateWindowEx: 실제 윈도우 생성
이제 등록된 클래스 이름을 사용하여 실제 윈도우를 생성합니다.

HWND hwnd = CreateWindowEx(
    0,                // 확장 스타일
    szWindowClass,    // 윈도우 클래스 이름
    szTitle,          // 윈도우 제목 (타이틀 바 텍스트)
    WS_OVERLAPPEDWINDOW, // 윈도우 스타일
    CW_USEDEFAULT, 0, // 윈도우 시작 위치 (x, y)
    800, 600,         // 윈도우 크기 (width, height)
    NULL,             // 부모 윈도우 핸들
    NULL,             // 메뉴 핸들
    hInstance,        // 프로그램 인스턴스 핸들
    NULL              // 추가 파라미터
);

성공적으로 생성되면, 해당 윈도우를 가리키는 고유한 핸들(HWND)이 반환됩니다. 만약 실패하면 NULL이 반환됩니다.

생성된 윈도우를 화면에 표시하려면 ShowWindow(hwnd, nCmdShow)와 UpdateWindow(hwnd)를 차례로 호출해야 합니다.

4. 메시지 루프와 윈도우 프로시저
윈도우는 생성되었지만, 이대로 두면 프로그램이 바로 종료됩니다. 프로그램이 계속 실행되면서 사용자의 입력을 기다리게 하려면 메시지 루프가 필요합니다.

MSG msg;
while (GetMessage(&msg, NULL, 0, 0))
{
    TranslateMessage(&msg);
    DispatchMessage(&msg);
}

GetMessage: 메시지 큐에서 메시지를 가져옵니다. 메시지가 없으면 메시지가 생길 때까지 기다립니다. WM_QUIT 메시지를 받으면 FALSE를 반환하여 루프가 종료됩니다.

TranslateMessage: 키보드 입력 메시지를 가공하여 WM_CHAR 메시지 등을 만들어줍니다.

DispatchMessage: 가져온 메시지를 해당 윈도우의 **윈도우 프로시저(WndProc)**로 보냅니다.

윈도우 프로시저 (LRESULT CALLBACK WndProc(...)) 는 DispatchMessage로부터 메시지를 받아 실제 처리를 하는 함수입니다. switch 문을 사용하여 메시지 종류에 따라 다른 작업을 수행합니다.

switch (message)
{
    case WM_DESTROY: // 윈도우가 파괴될 때 (예: 'X' 버튼 클릭)
        PostQuitMessage(0); // WM_QUIT 메시지를 보내 메시지 루프를 종료시킴
        break;
    default:
        return DefWindowProc(hWnd, message, wParam, lParam);
}

WM_DESTROY 메시지는 윈도우가 닫힐 때 발생합니다. 이때 PostQuitMessage(0)을 호출하여 메시지 루프에 WM_QUIT 메시지를 보내야 프로그램이 정상적으로 종료됩니다. 처리하지 않는 나머지 메시지들은 DefWindowProc으로 전달하여 기본 처리를 하도록 해야 합니다.
