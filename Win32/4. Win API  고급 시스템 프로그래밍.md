## Win API : 고급 시스템 프로그래밍
목표
파일 시스템, 메모리 관리, 멀티스레딩 등 운영체제의 핵심 기능을 직접 제어하는 방법을 학습합니다. 특히, 시간이 오래 걸리는 작업을 별도의 스레드에서 처리하여 UI가 멈추지 않는, 반응성 높은 프로그램을 만들 수 있게 됩니다.

## 1. 프로세스(Process)와 스레드(Thread)
`프로세스`: 현재 실행 중인 프로그램의 인스턴스입니다. 각 프로세스는 자신만의 독립된 메모리 공간을 가집니다. (예: 메모장, 크롬 브라우저)

`스레드`: 프로세스 내에서 실행되는 작업의 단위입니다. 모든 프로세스는 최소 하나 이상의 스레드(메인 스레드)를 가지며, 이 메인 스레드가 WinMain부터 시작하여 메시지 루프를 처리합니다.

하나의 프로세스는` 여러 개의 스레드`를 가질 수 있으며, 이를 멀티스레딩이라고 합니다. 스레드들은 프로세스의 메모리 공간을 공유하므로 서로 데이터를 주고받기 용이합니다.

## 2. 왜 멀티스레딩이 필요한가? (UI 응답성)
파일 검색이나 대용량 데이터 처리처럼 시간이 오래 걸리는 작업을 메인 스레드(UI 스레드)에서 처리하면 어떻게 될까요? 작업이 끝날 때까지 메시지 루프가 멈춰버립니다. 그 결과, 사용자는 창을 움직이거나 버튼을 클릭해도 프로그램이 아무런 반응을 하지 않는 '`응답 없음(Not Responding)`' 상태를 경험하게 됩니다.

해결책은 간단합니다. 시간이 오래 걸리는 작업은 별도의 `**작업자 스레드(Worker Thread)**`를 만들어 그곳에 위임하는 것입니다. 이렇게 하면 메인 스레드는 계속해서 메시지 루프를 돌며 사용자의 입력에 즉각적으로 반응할 수 있고, 작업자 스레드는 백그라운드에서 묵묵히 자신의 일을 처리하게 됩니다.

## 3. CreateThread와 스레드 간 통신
Windows에서는 `CreateThread 함수`를 사용하여 새로운 스레드를 생성할 수 있습니다. 이때, 새 스레드가 실행할 함수(스레드 함수)를 지정해 줍니다.

하지만 작업자 스레드가 UI(예: 리스트 박스)를 직접 수정하는 것은 매우 위험하며 금지되어 있습니다. UI 자원은 메인 스레드만 접근해야 합니다. 따라서 작업자 스레드는 결과를 찾으면 PostMessage 함수를 이용해 메인 윈도우에 "결과를 찾았어!"라는 메시지를 보내는 방식을 사용해야 합니다.

메인 윈도우의 WndProc은 이 메시지를 받아서 안전하게 UI를 갱신합니다.

## 4. 레지스트리(Registry)
`레지스트리`는 Windows 운영체제의 설정 정보를 담고 있는 계층적 데이터베이스입니다. 여기에 프로그램의 마지막 창 위치나 사용자 설정 같은 간단한 데이터를 저장하면, 다음 실행 시에 해당 설정을 복원하여 사용자 경험을 향상시킬 수 있습니다.

## 실습: 파일 검색기 만들기
이제 이 개념들을 종합하여, 지정된 경로에서 특정 텍스트가 포함된 파일을 찾아 목록에 보여주는 프로그램을 만들어 보겠습니다.

기능 요구사항:

검색할 경로와 검색어를 입력받는 UI를 제공한다.

[검색] 버튼을 누르면, 파일 검색은 별도의 작업자 스레드에서 시작된다.

검색 중에도 UI는 멈추지 않고 반응해야 한다.

작업자 스레드는 파일을 찾을 때마다 메인 윈도우에 메시지를 보내 결과를 리스트 박스에 실시간으로 추가한다.

프로그램 종료 시 마지막 검색 경로를 레지스트리에 저장하고, 시작 시 불러온다.
