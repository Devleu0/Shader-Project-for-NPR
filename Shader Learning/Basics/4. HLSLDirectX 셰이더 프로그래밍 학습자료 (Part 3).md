## HLSL/DirectX 셰이더 프로그래밍 학습자료 (Part 3)
> **따라 하기**: 이 문서의 코드는 셰이더만 담고 있어 C++ 호스트 프로그램이 필요합니다. 환경·행렬 규약·호스트 코드 구하는 법은 먼저 [실습 환경과 공통 규약](../0.%20실습%20환경과%20공통%20규약.md)을 읽으세요. 작성자가 직접 컴파일하지는 않았습니다.

이 문서는 중급 셰이딩 기법을 마스터한 개발자를 위한 고급 과정입니다. 렌더링된 장면에 영화 같은 효과를 더하는 후처리(Post-Processing)부터 GPU를 이용한 일반 목적 연산(GPGPU)까지, 현대 그래픽스 기술의 핵심을 다룹니다.

## 10주차: 후처리 효과 (Post-Processing)
 

렌더링 결과를 화면에 바로 그리지 않고, 텍스처에 저장하는 기법을 배웁니다.

전체 화면에 적용되는 필터 효과(블룸, 톤 매핑 등)를 구현합니다.


* 렌더 투 텍스처 (Render to Texture)
후처리의 핵심은 '2단계 렌더링'입니다.

* 1단계 (Off-screen Pass): 기존처럼 3D 장면을 렌더링하되, 결과를 화면(Back Buffer)이 아닌 별도의 텍스처, 즉 **렌더 타겟(Render Target)**에 저장합니다.

* 2단계 (Post-process Pass): 화면을 꽉 채우는 삼각형(또는 사각형) 하나만 렌더링합니다. 아래 예제는 정점 버퍼 없이 `Draw(3, 0)` 으로 그리는 방식입니다. 그리고 이 삼각형의 픽셀 셰이더에서 1단계에서 만든 렌더 타겟 텍스처를 샘플링하여, 다양한 필터 효과를 적용한 후 최종 화면에 출력합니다.

* 블룸 (Bloom) 효과
현실에서 매우 밝은 광원을 볼 때 빛이 주변으로 번져 보이는 현상을 시뮬레이션합니다.



렌더링된 장면에서 밝기가 특정 임계값을 넘는 부분만 추출하여 별도의 텍스처에 저장합니다.

이 '밝은 부분 텍스처'를 여러 번 흐릿하게(Blur) 만듭니다. (가우시안 블러 사용)

원본 장면 텍스처와 흐릿해진 밝은 부분 텍스처를 더하여 최종 결과를 만듭니다.

HLSL 실습 코드: 간단한 전체 화면 회색조(Grayscale) 필터 **(완성형)**
정점 셰이더는 정점 버퍼 없이 `SV_VertexID` 만으로 화면을 덮는 큰 삼각형을 만듭니다. 이 코드는 2단계(Post-process Pass)에서 사용됩니다.
```hlsl
// 1단계에서 렌더링된 장면이 담긴 텍스처
Texture2D SceneTexture : register(t0);
SamplerState SceneSampler : register(s0);

struct VS_OUTPUT
{
    float4 Pos : SV_POSITION;
    float2 Tex : TEXCOORD0;
};

// vertexID 0,1,2 -> UV (0,0), (2,0), (0,2) -> 클립 좌표 (-1,1), (3,1), (-1,-3) : 화면 전체를 덮는 삼각형
VS_OUTPUT VS(uint vertexID : SV_VertexID)
{
    VS_OUTPUT output;
    output.Tex = float2((vertexID << 1) & 2, vertexID & 2);
    output.Pos = float4(output.Tex * float2(2, -2) + float2(-1, 1), 0, 1);
    return output;
}

float4 PS(VS_OUTPUT input) : SV_Target
{
    // 렌더 타겟 텍스처에서 현재 픽셀의 색상을 가져옴
    float4 originalColor = SceneTexture.Sample(SceneSampler, input.Tex);

    // 색상을 회색조로 변환 (가중 평균)
    float luminance = dot(originalColor.rgb, float3(0.299, 0.587, 0.114));
    return float4(luminance, luminance, luminance, originalColor.a);
}
```
> **호스트에서 할 일 (10주차)**: ① 장면 크기의 텍스처를 `BIND_RENDER_TARGET | BIND_SHADER_RESOURCE` 로 만들고 RTV/SRV 생성, ② 1단계: RTV 를 바인딩해 장면 렌더, ③ 2단계: 백버퍼 RTV 를 바인딩(이때 장면 RTV 는 해제되어야 SRV 로 읽힘) → 입력 레이아웃 `nullptr`, 토폴로지 `TRIANGLELIST`, VS/PS 설정, SRV 와 샘플러 바인딩, `Draw(3, 0)`.

 10주차 연습 문제
회색조 필터 대신 세피아(Sepia) 톤 필터를 구현해보세요. (정해진 세피아 변환 행렬을 검색하여 적용)

화면의 특정 영역(예: 가장자리)을 어둡게 만드는 비네트(Vignette) 효과를 추가해보세요. (UV 좌표를 이용해 화면 중앙으로부터의 거리를 계산)

## 11주차: 지오메트리 & 테셀레이션 셰이더
 

정점 셰이더 이후 단계에서 GPU를 이용해 동적으로 기하 도형(Geometry)을 생성, 수정, 제거하는 방법을 배웁니다.


* 지오메트리 셰이더 (Geometry Shader, GS)
정점 셰이더(VS)와 래스터라이저 사이에 위치하며, VS에서 넘어온 기본 도형(Primitive: 점, 선, 삼각형)을 입력으로 받습니다. GS는 이 기본 도형을 그대로 통과시키거나, 아예 제거하거나, 완전히 새로운 여러 개의 기본 도형으로 확장할 수 있습니다.

활용 예시:

하나의 점(Point)을 입력받아 사각형(Quad)으로 확장하여 파티클 렌더링

삼각형을 입력받아 법선 방향으로 확장하여 '털(Fur)'이나 '잔디' 생성

* 모델의 외곽선(Outline) 렌더링

* 테셀레이션 셰이더 (Tessellation Shaders)
저해상도(Low-poly) 모델을 입력받아 GPU가 실시간으로 수많은 삼각형으로 잘게 쪼개어 매우 부드럽고 디테일한 표면을 만들어내는 기술입니다. 두 개의 새로운 셰이더 단계로 구성됩니다.

* 헐 셰이더 (Hull Shader, HS): 입력된 거친 패치(Patch)를 얼마나 잘게 쪼갤지(Tessellation Factor) 결정합니다. 카메라와의 거리에 따라 쪼개는 정도를 조절하여 동적 LOD(Level of Detail)를 구현할 수 있습니다.

* 도메인 셰이더 (Domain Shader, DS): 헐 셰이더의 결정에 따라 실제로 생성된 세부 정점들의 최종 위치를 계산합니다. 디스플레이스먼트 맵(Displacement Map)을 사용하여 표면에 실제적인 높낮이를 부여할 수 있습니다.

HLSL 실습 코드: (지오메트리 셰이더) 점을 사각형 빌보드로 확장하기 **(완성형)**
핵심은 **크기를 투영 전(월드 공간)에 더한다**는 것입니다. 클립 공간 좌표에 직접 더하면 원근 나눗셈 때문에 크기가 깨집니다.
```hlsl
cbuffer CBufferGS : register(b0)
{
    float4x4 ViewProj;
    float4   CameraRight; // 카메라의 오른쪽 축 (월드 공간, xyz)
    float4   CameraUp;    // 카메라의 위쪽 축 (월드 공간, xyz)
    float4   BillboardSize; // x = 반너비(halfSize)
}

struct VS_OUTPUT { float3 WorldPos : POSITION; };           // VS 는 월드 위치를 그대로 전달
struct GS_OUTPUT { float4 Pos : SV_POSITION; float2 Tex : TEXCOORD0; };

VS_OUTPUT VS(float3 pos : POSITION) { VS_OUTPUT o; o.WorldPos = pos; return o; }

[maxvertexcount(4)]
void GS(point VS_OUTPUT input[1], inout TriangleStream<GS_OUTPUT> stream)
{
    float3 center = input[0].WorldPos;
    float  h = BillboardSize.x;
    float3 right = CameraRight.xyz * h;
    float3 up    = CameraUp.xyz * h;

    // 삼각형 스트립 순서: 좌상 -> 우상 -> 좌하 -> 우하
    float3 corners[4] = { center - right + up, center + right + up, center - right - up, center + right - up };
    float2 uvs[4]     = { float2(0,0), float2(1,0), float2(0,1), float2(1,1) };

    [unroll]
    for (int i = 0; i < 4; ++i)
    {
        GS_OUTPUT o;
        o.Pos = mul(float4(corners[i], 1.0f), ViewProj);
        o.Tex = uvs[i];
        stream.Append(o);
    }
}
```
> **호스트에서 할 일 (11주차)**: 정점 버퍼에 점(위치 float3)만 넣고 토폴로지를 `D3D11_PRIMITIVE_TOPOLOGY_POINTLIST` 로 설정, `CreateGeometryShader` 로 GS 를 만들어 `GSSetShader`/`GSSetConstantBuffers`. `CameraRight/Up` 은 뷰 행렬에서 얻습니다 (행 벡터 규약의 뷰 행렬이면 각각 첫 번째/두 번째 **열**). PS 는 `GS_OUTPUT` 을 입력으로 받습니다. 스트림 타입 이름은 `TriangleStream` 입니다 (`TriangleStrip` 이 아님).

## 12주차: 컴퓨트 셰이더 (Compute Shader)
 

3D 렌더링 파이프라인에서 벗어나, GPU를 대규모 병렬 계산 장치로 활용하는 방법을 배웁니다. (GPGPU)


* GPGPU (General-Purpose computing on GPU)
수천 개의 코어를 가진 GPU의 막강한 병렬 처리 능력을 3D 그래픽스뿐만 아니라 물리 시뮬레이션, 데이터 분석, 인공지능 등 일반적인 계산 작업에 활용하는 기술입니다. **컴퓨트 셰이더(CS)**는 이를 위한 DirectX의 핵심 기능입니다.

* 컴퓨트 셰이더의 작동 방식
CS는 VS, PS와 완전히 독립적으로 작동합니다.

* 스레드 & 그룹 (Threads & Groups): CS는 수많은 '스레드(Thread)' 단위로 실행됩니다. 이 스레드들은 '스레드 그룹(Thread Group)'으로 묶여 관리됩니다. 우리는 C++ 코드에서 몇 개의 스레드 그룹을 실행할지(Dispatch) 결정하고, 셰이더 코드 내에서 각 스레드가 그룹 내에서 어떤 ID를 갖는지 알 수 있습니다.

* 데이터 접근: UAV (Unordered Access View): CS는 렌더링이 아닌 데이터 처리가 목적이므로, 자유롭게 읽고 쓸 수 있는 메모리 버퍼가 필요합니다. UAV가 바로 이 역할을 합니다. Structured Buffer나 텍스처를 UAV로 바인딩하여 CS에서 데이터를 읽고 계산 결과를 다시 쓸 수 있습니다.

HLSL 실습 코드: (컴퓨트 셰이더) 파티클 위치 업데이트 **(완성형)**
```hlsl
struct Particle
{
    float3 Pos;
    float3 Vel;
};

cbuffer CBufferCS : register(b0)
{
    float DeltaTime;
    uint  ParticleCount;
    float2 padding;      // 16바이트 정렬용
}

// 읽기/쓰기가 가능한 파티클 데이터 버퍼 (UAV)
RWStructuredBuffer<Particle> ParticleBuffer : register(u0);

[numthreads(256, 1, 1)]
void CS(uint3 dispatchThreadID : SV_DispatchThreadID)
{
    uint index = dispatchThreadID.x;
    if (index >= ParticleCount) return;   // 스레드 수는 그룹 크기의 배수로 올림되므로 반드시 범위를 검사

    Particle p = ParticleBuffer[index];

    // 간단한 물리 계산 (중력 적용)
    p.Vel += float3(0, -9.8f * DeltaTime, 0);
    p.Pos += p.Vel * DeltaTime;

    ParticleBuffer[index] = p;
}
```
> **호스트에서 할 일 (12주차)**: ① 구조화 버퍼를 `D3D11_RESOURCE_MISC_BUFFER_STRUCTURED`, `BIND_UNORDERED_ACCESS`, `StructureByteStride = 24`(float3 두 개) 로 생성하고 UAV 생성, ② `CSSetShader`, `CSSetUnorderedAccessViews(0,1,…)`, `CSSetConstantBuffers(0,1,…)`, ③ `Dispatch((ParticleCount + 255) / 256, 1, 1)` — `numthreads` 값(256)과 올림 계산이 일치해야 합니다.

## 13주차: 셰이더 최적화
 

셰이더 코드의 성능 병목 지점을 찾아내고, 이를 개선하는 다양한 기법을 학습합니다.


* 프로파일링 (Profiling)
최적화의 첫걸음은 추측이 아닌 측정입니다. PIX for Windows나 RenderDoc 같은 그래픽스 디버거/프로파일러를 사용하여 GPU가 각 드로우 콜(Draw Call)과 셰이더 단계에서 얼마나 많은 시간을 소모하는지 정확히 측정해야 합니다.

* 산술 연산 최적화 (Arithmetic Optimization)

`x * y + z` 는 컴파일러가 대부분 자동으로 `mad` 로 합쳐 주므로 직접 `mad` 를 쓸 필요는 거의 없습니다. 이런 미시 최적화는 반드시 프로파일링으로 효과를 확인한 뒤에만 하세요.

나눗셈(a / b)은 곱셈보다 일반적으로 비쌉니다. 같은 값으로 여러 번 나눈다면 역수를 한 번 구해 곱하는 것이 유리할 수 있습니다 (단, 이것도 측정으로 확인).

정밀도가 중요하지 않을 때는 `min16float` 로 16비트 연산을 요청할 수 있지만, **데스크톱 GPU 에서는 이를 32비트로 처리하는 경우가 많아** 효과가 보장되지 않습니다 (모바일 GPU 에서 이득이 큼). HLSL 의 `half` 는 DX11 에서 `float` 와 동일하게 취급됩니다.

* 분기문 회피 (Avoiding Branches)
GPU는 수많은 스레드가 동일한 명령을 동시에 실행할 때 가장 효율적입니다. 셰이더 내의 if/else 문은 스레드들의 실행 경로를 갈라놓아('Divergence') 심각한 성능 저하를 유발할 수 있습니다.

* 대체 기법: step, lerp, saturate, min, max 같은 내장 함수들을 창의적으로 조합하여 if문과 동일한 결과를 내도록 코드를 수정할 수 있습니다.

예시:
```hlsl
// 나쁜 예: 분기문 사용
float value;
if (x > 0.5) {
    value = a;
} else {
    value = b;
}
```
```hlsl
// 좋은 예: lerp 함수 사용
float t = step(0.5, x); // x > 0.5 이면 1, 아니면 0
float value = lerp(b, a, t); // t가 0이면 b, 1이면 a
```
## 14주차: 최종 프로젝트
 

Part 1, 2, 3에서 배운 모든 지식을 총동원하여 자신만의 독창적인 그래픽 데모를 제작합니다.

프로젝트 아이디어 제안
* PBR (Physically Based Rendering) 셰이더 구현: 금속(Metallic), 거칠기(Roughness) 등의 물리 기반 속성을 사용하여 매우 사실적인 재질을 렌더링하는 셰이더 시스템을 만들어봅니다.
* 컴퓨트 셰이더 기반 파티클 시스템: 수만~수십만 개의 파티클이 상호작용하거나 복잡한 힘의 장(Force Field)에 의해 움직이는 화려한 시뮬레이션을 구현합니다.

* 지연 렌더링 (Deferred Shading): 수많은 동적 광원을 효율적으로 처리할 수 있는 고급 렌더링 기법을 구현합니다. (1차: G-Buffer 생성, 2차: 조명 계산)

* 테셀레이션을 이용한 동적 지형 렌더링: 카메라 거리에 따라 디테일이 실시간으로 변하는 광활한 지형을 렌더링합니다.
